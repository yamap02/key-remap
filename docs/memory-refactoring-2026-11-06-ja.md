# メモリ消費を抑えるGUIリファクタリング

実施日: 2026-11-06（JST）。実装コミット: `374d045`。
調査の出発点は[メモリ調査レポート](memory-assessment-2026-11-06-ja.md)。

## 変更内容

- 長期間常駐する `AppState` / `RuntimeClient` を `@Observable` から `ObservableObject` に置き換えた。UIに必要な値だけを `@Published` にし、Task・XPC接続・通信中フラグ・HIDオブジェクトを変更通知から除外した。
- アプリの所有を `@StateObject`、各画面を `@ObservedObject` に統一。設定編集用のBindingと自動保存は維持した。
- 状態応答とデバイス一覧は同じ値なら通知しない。デバイスの並び順には同名の場合のID比較も入れた。前面アプリも変更時のみ通知する。
- UIの未使用の全アプリ走査を削除。ドライバ状態は最新の応答から直接算出し、3秒遅れて反映される重複状態をなくした。
- EventViewerの履歴を専用の `EventLog` に分離。空バッチでは通知せず、最新2,000件だけを一度の代入で公開する。イベント追加から設定画面全体への通知を切り離した。
- 閉じる・一時停止・権限喪失でViewerの世代を更新し、古い要求への応答を破棄する。権限やAgentの生存確認を失うと既存履歴も消す。一時停止中の重複した停止要求も抑制した。
- キー名辞書・逆引き辞書・カテゴリ候補を共有し、繰り返し生成や線形検索を削減。単純リマップの一覧を `LazyVStack` にした。

3秒ごとのCore状態取得は、リマップを継続する生存確認も兼ねるため維持した。Coreの入力・出力ロジック、AXでの安全確認、500 msの鮮度条件、設定の競合保存方式は変更していない。

Agentのイベント駆動化、設定キャッシュ、設定UIの別プロセス化、全面的なAppKit化は今回のGUIヒープ問題の修正には必要と判断しなかったため含めていない。

## メモリ測定の読み方

型別の実測値は[測定抜粋](memory-refactoring-2026-11-06-evidence.txt)に記録した。

| 対象 | 状態 | physical footprint |
| --- | --- | ---: |
| 旧版 build 17 / PID 1673 | 約7日稼働 | 700.2 MiB |
| 旧版 build 17 / PID 42337 | 再起動後、「その他」画面 | 51.6 → 51.7 MiB |
| 更新版 build 20 / PID 43991 | 起動後、サービス復帰前、「権限」画面 | 47.8 MiB |

旧版の再起動後、約30秒でObservationTracking.Idの辞書が71→79個、Entryの辞書が20→28個に増えた。更新版の短時間測定ではそれぞれ19個・10個、malloc割当は約29.4 MiBだった。フレームワーク内部でもObservationを使うため、更新後も完全にゼロにはならない。

**700→48 MiBという差を、リファクタリングだけの削減効果とは扱わない。** 再起動の影響が大きく、画面・接続状態・稼働期間も異なる。今回の修正は巨大化していたアプリモデルのObservation追跡経路を取り除くものであり、24時間・7日間の安定性を実証したものではない。ユーザーの指示に従い、長時間の反復測定は行っていない。

## インストールと権限

ReKeyAgentのアクセシビリティはユーザーの指示でオフにした。通常のリマップには不要。EventViewerで他アプリの入力を表示するには、従来どおりAgentの許可が必要になる。

更新時にad-hoc署名が変わり、CoreとAgentが `needs LWCR update` / `EX_CONFIG` になった。ReKeyの既存バックグラウンド項目をオフ→オンにして署名登録を更新した。その後Coreと仮想HIDの接続を確認したが、Coreの入力監視は新しい署名への再登録が必要になった。

入力監視の単純なオフ→オンでは許可が反映されなかったため、古い `rekey-core` の項目を外し、現在の `/Applications/ReKey.app/Contents/Library/HelperTools/rekey-core` を追加してサービスを再起動した。

最終画面で「入力監視 許可済み」「仮想 HID ドライバ 接続済み」「入力サービス 稼働中」「リマップ有効」を確認した。アクセシビリティはオフのまま。物理キーボードを用いた全マッピングの再確認や、以前の画面スリープ問題の再検証は今回の確認範囲に含めていない。
