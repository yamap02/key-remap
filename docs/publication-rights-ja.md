# 公開・配布前の権利確認

最終更新: 2026-11-14

この文書は ReKey のソース公開とソフトウェア配布に向けた確認事項を記録する。
記載・ライセンス文の追加だけで権利監査が完了したことにはならない。
未確認の項目は配布担当者が確認し、対象コミット・成果物・根拠・確認日を記録する。
技術面の出荷条件は [Sparkle 配布手順](sparkle-distribution-ja.md) と
[要件表](requirements.md) を併せて確認する。
ソース公開と実行可能な製品の出荷は別々に判断する。

## 現時点で確認したこと

- [ReKey のライセンス](../LICENSE.md) は、権利を保有する独自部分に
  Unlicense を適用し、第三者のコード・ライブラリ・素材を対象から除外している。
- [第三者ライセンス一覧](../Resources/Licenses/README.md) にアプリの依存物と、
  リポジトリに追加で含まれる spdlog・fmt・Boost.UT・debug_assert を記載した。
  個別ファイルの著作権表示と通知文も維持する。
- `scripts/build-app.sh` は `Resources/Licenses/` をアプリにコピーし、
  ReKey・Sparkle・VirtualHID 本体のライセンスも追加する。
  実際の公開用 app・pkg・更新 zip での収録確認はリリースごとに行う。
- 現在の Git 管理対象には `Vendor/VirtualHID/dist/` の公式 pkg 8.6.0 が1個ある。
  旧版70個はコミット `17bc942` で削除されているが、それ以前の履歴には残る。
  残存 pkg の内部と過去の Git 履歴について、権利監査の完了を示すものではない。
- [アイコンの制作記録](../Resources/Icons/README.md) がある。
  出典記録は名称・図案の商標調査や第三者作品との類似性確認の代わりにはならない。

## ソース公開前に確認すること

- [ ] **公開する全ファイルと履歴の範囲**: ビルドで未使用の Vendor ソース、
  サンプル、テスト、文書、画像、バイナリも対象にする。
  `scripts/check-vendored-notices.py` はコンパイル対象のヘッダー系列の確認であり、
  リポジトリ全体・pkg 内部・履歴の完全監査ではない。
- [ ] **独自部分の権利者**: 勤務先・委託元・共同開発者との契約、持込みコード、
  コピーしたサンプルや素材を確認し、公開・ライセンス付与できる根拠を残す。
  AI が生成したコードも、既存作品の転載や適用ライセンスの確認を省略しない。
- [ ] **Unlicense の選択**: 他者による改変・再配布・販売を広く認める方針を確認する。
  第三者の権利を一括して放棄・再許諾するものとして扱わない。
  外部貢献の条件は [CONTRIBUTING.md](../CONTRIBUTING.md) に従う。
- [ ] **第三者の通知文**: 使用版・取得元・著作権表示・全文・改変表示の要否を確認する。
  MIT 等の原文を単なる URL や日本語要約だけで置き換えない。
  新しい依存物や埋込みコードを追加したら一覧も更新する。
- [ ] **秘密情報と非公開情報**: 署名秘密鍵、証明書の秘密鍵を含むエクスポート、
  API トークン、個人情報、第三者の非公開資料が現在のファイルと公開する履歴に
  含まれないことを確認する。`.gitignore` は過去のコミットから情報を消さない。

## 公式ドライバ pkg の扱い

VirtualHID 本体の [Unlicense](../Vendor/VirtualHID/LICENSE.md) はソース・バイナリの
再配布と商用利用を認める。ただし、それだけで pkg 内の全依存物の告知が十分とは
判断しない。現在残る8.6.0と、過去の履歴に含まれる旧版の pkg の内部監査は未完了。

- [ ] **公開する pkg の範囲を決定**: 不要な過去版を含め、保持・公開する理由を確認する。
  利用者を互換性のある公式配布物へ案内する方法も検討する。
- [ ] **再配布する場合**: 各対象 pkg の版、配布元、ハッシュ、署名、公証、
  内包する第三者部品と必要な通知文を確認して記録する。
  公式パッケージを ReKey 自身が制作・署名したもののように表示しない。
- [ ] **除外する場合**: 作業ツリーからの削除だけでは公開履歴から消えないことを踏まえ、
  公開する履歴も含めて扱いを決める。履歴の書換えは別途計画して実施する。

## 製品名・ロゴ・説明文

- [ ] **ReKey の名称調査**: 配布対象国で ReKey と近い表記・読み、関連する商品・役務を
  確認する。日本の登録・出願情報は [J-PlatPat の商標検索](https://www.j-platpat.inpit.go.jp/t0100)
  を参照する。検索結果・対象地域・確認日を残す。現時点で名称の使用可能性は未確認。
- [ ] **画像・ロゴの確認**: アプリアイコン、スクリーンショット、宣伝画像について、
  制作元と利用条件、第三者ロゴ・既存作品との類似性を確認する。
  AI 生成という制作方法だけで権利侵害がない、独占できるとは判断しない。
- [ ] **第三者との関係の表示**: README と配布ページに独立したプロジェクトであることを
  示し、Karabiner・pqrs.org・Apple による公式製品、提携、承認、推奨と誤認させない。
  Apple の名称・ロゴ等は [公式ガイドライン](https://www.apple.com/legal/intellectual-property/guidelinesfor3rdparties.html)
  を確認する。互換性の説明とロゴの使用許諾を混同しない。
- [ ] **特許等の確認範囲**: OSS ライセンス表示の確認だけで特許非侵害や名称の安全性が
  証明されたとはしない。特許調査は未実施。具体的な懸念や事業上の必要に応じて、
  対象技術・国を絞って専門家に確認する。

## アプリ・独自ドライバを配布する前に確認すること

- [ ] **実成果物の通知文**: 公開する app の `Contents/Resources/Licenses/`、
  初回導入 pkg 内の app、更新 zip 内の app に必要な全文と著作権表示があることを確認する。
  Sparkle は外部部品の告知を含む LICENSE 全体を同梱する。
  利用者向けの参照先は [インストールと更新](install-update-ja.md) に記載する。
- [ ] **Apple の契約・配布条件**: 自分の Developer アカウントで同意した最新版の
  [Apple の契約](https://developer.apple.com/support/terms/) と配布方式に従い、
  署名・公証を行う。署名・公証は第三者著作物の利用許諾や権利監査の代わりにはならない。
- [ ] **独自 DriverKit 拡張を配布する場合**: 自分の Team、bundle ID、必要な entitlement と
  provisioning profile を用意する。上流ソースのライセンスから第三者の署名資格や
  Apple の承認を引き継げるとは判断しない。
  [Apple の DriverKit 案内](https://developer.apple.com/system-extensions/) を確認する。
- [ ] **独自ドライバの USB 識別子**: 上流の VID/PID・製造元・製品名をそのまま流用せず、
  適用条件と使用可能性を確認する。現状の上流ソースには共有 ID の使用条件が
  [USB-IDs-for-free.txt](../Vendor/VirtualHID/src/DriverKit/vendor/v-usb/usbdrv/USB-IDs-for-free.txt)
  と [FAQ](../Vendor/VirtualHID/src/DriverKit/vendor/v-usb/usbdrv/USB-ID-FAQ.txt) に含まれる。
  これらの文書があるだけで独自実装への適合確認済みとはしない。

## 確認記録

公開判断時に、以下を具体的な値と根拠へのリンクで記録する。
未完了の項目を、文書を作成したことだけを理由に完了へ変更しない。

| 項目 | 記録内容 |
| --- | --- |
| 対象 | コミット、公開するブランチ・タグ・履歴の範囲 |
| 成果物 | ファイル名、版、ハッシュ、配布先 |
| 権利・通知 | 対象部品、取得元、ライセンス、通知文の収録場所 |
| 名称・素材 | 調査対象国、検索・確認内容、制作元・許諾の根拠 |
| 結果 | 確認日、確認者、未解決事項、公開・配布の判断 |
