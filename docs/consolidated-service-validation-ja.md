# 入力サービス統合・権限整理の実装と検証

2026-10-25（JST）。実装コミット `598ae9b`。インストール先 `/Applications/ReKey.app`、最終 build 6。

## 変更

- ReKey 固有の常駐は UI / Agent / Core の3プロセス。従来の4から1つ削減し、root は Core の1プロセスに集約した。公式 Karabiner Daemon / DriverKit と Apple の UI サービスは別途必要。
- Core が仮想HIDクライアントを保持する。出力は別スレッドへ4096件の有界キューで渡し、入力処理からソケット送信待ちを除いた。独自の共有メモリとプロセス間通知ソケットは廃止。
- 押下数をキーごとに数え、複数キーボードが同じキーを押している間の早すぎる解放を防ぐ。通常キー・修飾キー・consumer・Apple vendor keyboard / top case の出力を維持。
- 出力セッション変更時は古いキュー内容を破棄し、全レポートと物理キーボードの占有をリセットする。入力ループが2秒以上停止した場合はプロセスを終了して、OSと接続デーモンにHID接続を解放させる。
- SIGTERM / SIGINT はメインループを停止し、出力ワーカーとクライアントの正常な破棄を通して終了する。未接続時のリセットは送信要求を発生させず、エラーのフィードバックループを防ぐ。
- 旧 `rekey-vhid` の実行ファイルは配布しない。旧 plist は SMAppService の解除用にだけ残し、新規登録しない。パッケージは置換前に旧 Core / VHID を停止し、更新後 UI が旧 VHID 登録を解除する。公式の共有デーモンは解除しない。
- サービスの再登録直後に macOS が一時的に返す EPERM について、承認状態を確認しながら最大5回の限定再試行を行う。

## アクセシビリティ

通常のリマップ、プロファイル切替、アプリ条件、入力ソース条件、ユーザーアクションを AX 許可の必須条件にしていない。権限画面にも「EventViewer 使用時のみ必要」と表示する。

EventViewer の入力表示要求が Core にある間だけ、Agent が AX の入力欄 role / subrole を確認する。Agent 側の許可は最終応答から500 msで期限切れとなり、切断・表示終了の通知で無効にする。これはAXを使用するコードの稼働期限であり、macOSの許可そのものを自動で解除する仕組みではない。

EventViewer は AX 未許可時でも表示要求だけを送れるが、Core は安全な入力欄の確認ができるまでイベントを返さない。パスワード欄、Secure Event Input、読み取り失敗、古い状態での抑止を維持する。表示停止・ウィンドウ終了時は要求を止め、履歴を破棄する。

## 利用者の環境で行った権限操作

入力監視は現在の `/Applications/ReKey.app/Contents/Library/HelperTools/rekey-core` で再登録した。旧版名 `ReKey-before-setup-fix.app` の入力監視はオフにした。Agent の AX はオン・オフを検証し、通常利用向けに最後はオフに戻した。

開発用 ad-hoc 署名の更新に伴い、通常のシステム設定でバックグラウンド項目のオフ→オン、Core / Agent の該当許可の再追加を行った。OSの認証は利用者がTouch IDで実施した。署名・TCC・launchdの保護を回避する変更はしていない。
