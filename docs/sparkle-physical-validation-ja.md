# Sparkle 更新の実機検証手順と記録

この手順は **未実施**。自動テストの成功を、root 所有 app の更新や物理入力の成功とみなさない。公開先、製品 ID、Team ID、実証明書、配布用鍵が未決定のため、ここでは試験結果を記入しない。実行後に各ケースの実測結果と証拠を記録し、[配布手順](sparkle-distribution-ja.md) の出荷ゲートと照合する。

## 準備

1. クリーンな専用試験 Mac と管理者を用意する。普段の入力環境では行わず、別の入力手段と画面共有または復旧手段を確保する。物理キーボードの占有が解除されない場合は試験を止め、OS のバックグラウンド項目を無効にするか Mac を再起動する。
2. 同じ実際の製品 ID・Team ID・Sparkle 公開鍵で署名・公証した旧 build と新 build を用意し、新 build の整数 build 番号を大きくする。初回導入用 pkg と更新 zip は同一の新 app から作成する。ドライバ、ライセンスとシステム機能拡張・入力監視の承認は配布手順に従って確認する。
3. 外部に公開しない試験用 HTTPS feed を用意し、試験 Mac から取得できることを確認する。異常系の feed・ファイルは試験専用の別環境で作り、本番の鍵や既存 asset を変更しない。公開 GitHub Releases の HTTPS 取得は公開先が確定した後に別途検証する。
4. 試験専用の設定を作り、パス、内容のハッシュ、旧 build、入力サービスと Agent の登録・承認状態、キーボードの入力・変換状態を記録する。設定や入力ログをそのまま公開しない。各試験は旧版と初期状態を復元してから個別に実施する。
5. インストール前後に `codesign --verify --deep --strict /Applications/ReKey.app`、`xcrun stapler validate /Applications/ReKey.app`、`spctl --assess --type execute --verbose=2 /Applications/ReKey.app` を実行し、結果を保存する。`ls -ldeO` 等で app・Agent・Core と親ディレクトリの所有者、書込み権限、ACL を確認する。全階層の確認にはシンボリックリンクも含め、root:wheel と書込み不可という Core の成立条件を満たすことを確かめる。

## ケースと合格条件

| ケース | 操作 | 確認する結果 |
| --- | --- | --- |
| 初回導入 | ドライバと初回 pkg を導入し、OS が求める承認を行う | 署名・公証、登録状態、Core の入力監視、Agent の状態、物理入力と変換が正常 |
| 更新なし | 最新版で手動確認し、自動確認も有効にする | 更新なしと表示され、設定・登録・入力が変化しない |
| 通常更新 | 旧版で更新を選択し、管理者認証して新版へ進む | 置換前に入力が解放され、置換後は新 build、root 所有と権限、署名、設定、以前有効だった Core/Agent と XPC 接続が維持される |
| 設定未保存・競合 | 更新選択直前に設定を編集し、別プロセスでも同じ設定を変更する | 保存競合が通知され、更新は進まず、どちらの変更も無言で上書きされない |
| 署名不正 | 試験鍵の異なる feed、または同じ長さで改ざんした更新 zip を使う | 検証失敗で置換されず、旧版と設定を保持し、停止済みサービスを安全に復旧できる |
| 通信失敗 | 試験 feed または zip の取得を遮断する | エラーが示され、置換されず、サービスと物理入力を復旧できる |
| 管理者認証の拒否 | 通常更新の認証ダイアログでキャンセルする | 旧 app のまま、入力占有が残らず、再試行またはキャンセルから復旧できる |
| ダウンロード・展開中断 | 試験環境で通信遮断や app の終了を各段階で行う | 旧 app と設定を保持し、次回起動で保留状態と復旧手段が分かる。保留中に勝手に入力を再取得しない |
| 保留後の再起動・取消し | 更新を保留し旧版を再起動後、再開と取消しを別々に試す | 保留中はサービスを停止し、取消し後は元々有効だったもののみ復旧。承認待ちや無効のものを勝手に有効化しない |
| 異常終了 | `disable_on_quit` の両値で更新中と通常時に UI を終了する | 更新中・中断後は物理キーが占有されたままにならない。通常時は設定に応じた動作と更新中との差を記録する |
| pkg の中断・旧版移行 | 旧 UI・Agent が稼働中の導入、停止後の中断、旧開発版からの移行を別々に試す | 稼働中は置換前に拒否。中断後も入力を復旧可能で、旧登録・TCC の状態を確認できる |
| 再起動後 | 成功・失敗・中断後に各々 Mac を再起動する | 認証状態、登録、設定と物理入力を確認し、古い Core/Agent が残らない |

すべてのケースで、UI 上の成功表示だけでなく、実際の物理入力、プロセス・登録、設定、OS 権限を照合する。停止・再登録の成否を推測せず、検証できない場合は「未確認」と記録する。異常系で実機を強制終了する場合は、別入力手段を先に確認する。

## 記録テンプレート

各ケースにつき次を記録する。秘密鍵、認証情報、個人の入力内容や設定本文は記録しない。

```text
ケース / 実施日時 / 担当:
Mac・macOS / ドライバ版 / 製品 ID / Team ID:
旧・新の表示版と build / アーカイブ SHA-256 / feed の識別:
初期状態（Core・Agent 登録と承認、入力、disable_on_quit）:
実施した操作と中断・拒否の時点:
結果: 合格 / 失敗 / 未実施 / 判定不能
観測（所有権・権限・ACL、署名・公証、物理入力、設定ハッシュ、登録・XPC）:
証拠の保存先（機密を除去） / 復旧操作 / 残課題:
```

通常 app 更新で root 所有・権限、入力解放、サービス再接続のいずれかが成立しなければ、この方式を出荷可能としない。原因を調べて再試験し、通常更新を成立させられない場合に限り、管理者認証を伴う pkg 更新を設計・検証する。現状の pkg は中断後の自動復旧や Agent の移行が未完了であり、そのまま代替の完成版として扱わない。
